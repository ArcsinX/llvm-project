Semantic Navigation & Disambiguation

Distinguishing types vs. values and traversing included headers accurately.

1. Syntactic Context (isTypeContext)

  • ClangdServer::adjustParseInputs
    Followed by :: → Type context. Jumps to class ClangdServer in header, not constructor in .cpp!
  • ClangdServer::ClangdServer(...)
    1st is class in .h; 2nd before ( is constructor.
  • Foo Foo; Foo.x = 1;
    1st is struct Foo; 2nd & 3rd are local variable Foo.

2. Transitive Header BFS Search

  • Bounded Breadth-First Search (BFS) over #include directives.
  • Prioritizes quoted project headers first.
  • Avoids recursive explosion into standard library internals (<__algorithm/*>).
  • #include <vector>: Direct jump to system standard library headers.

🤖 Why Clang-Pseudo Over Tree-sitter for AI

Cross-file heuristics can be built on either parser. But Clang-Pseudo's advantages compound across every layer:

AI Scenario Tree-sitter Limitation Clang-Pseudo Advantage
🛡️ LLM Output Validation Handcrafted grammar silently accepts invalid C++ or rejects valid C++. Unreliable signal. ISO Standard BNF: formally correct accept/reject. AI can trust the verdict.
🎯 Ambiguity-Aware Reasoning Eagerly picks one interpretation. X * y; forced to one parse—AI is blind to alternatives. Parse Forest (DAG) retains all valid parses. AI scores alternatives with broader context.
🌐 Cross-File Header Quality You can build cross-file on Tree-sitter, but headers break it worst: <vector> is dense with #ifdef and templates → widespread (ERROR) nodes that poison symbol resolution. 🤖 "Custom Preprocessor on Tree-sitter?"

A custom DirectiveTree-like preprocessor closes one gap. The deeper ones are architectural:

Gap Fixed by Custom Preprocessor? Why / Why Not
#ifdef branch selection ✅ Yes Feasible to build, similar to DirectiveTree
Macro expansion
Q_OBJECT, BOOST_*		 ❌ No Requires reimplementing the C preprocessor (## pasting, variadic macros, _Pragma). Clang-Pseudo uses GLR Opaque nodes; Tree-sitter emits (ERROR).
Grammar ambiguity
X*y;, T(x);		 ❌ No Fundamental: Tree-sitter's static prec() forces one parse. Clang-Pseudo's GLR Parse Forest retains all. No preprocessor can change the parsing algorithm.
Lexer edge cases
>>, raw strings, UCN		 ❌ No Tree-sitter uses its own lexer. Clang-Pseudo uses clang::Lexer — every C++ lexical edge case handled.

A custom preprocessor gets you ~30% of the way. The remaining 70% — grammar, lexer, declaration classification — are properties of the parser itself.

Study 1: Preprocessor Resilience (Branch Brackets)

Branch Brackets (#if / #else)

#define USE_V2 1
#if USE_V2
class DataService {
#else
class LegacyService {
#endif
public:
    void sync();
};
void run() {
    DataService svc; // GTD on 'DataService' -> Line 5
    svc.sync();      // GTD on 'sync' -> Line 10
}

⚠️ Architectural Dilemma: Opening { appears in two competing branches with one closing }. Common in cross-platform code.

Tree-sitter Breakdown vs. DirectiveTree

❌ Tree-sitter (Flat AST): Parses #if/#else as inline syntax nodes. Two unclosed { before #else break the LR parser → cascaded (ERROR) nodes swallow declarations → GTD FAILS. Regex/indent heuristics cannot know which branch is active.

✅ Clang-Pseudo (DirectiveTree): Evaluates #if USE_V2 and prunes #else before parsing. Parser receives a perfectly balanced stream → Zero heuristics! GTD SUCCEEDS!

Study 2: Real ISO Grammar vs. Handcrafted DSL

Valid Standard C++20 (ISO N4860)

template <typename T>
concept Serializable = requires(T x) {
    x.serialize();
};

template <Serializable T>
class DataPipeline {
public:
    void process(T data);
};

void run() {
    DataPipeline<int> pipeline; // GTD -> Line 8
    pipeline.process(42);
}
// On template param: GTD on 'Serializable' -> Line 2

💡 Language Reality: Concepts, requires expressions & constrained template heads are standard C++20 ISO productions.

Handcrafted DSL vs. Official ISO BNF

❌ Tree-sitter (grammar.js): Handwritten DSL lacks C++20 type-constraint parameter heads (template <Serializable T>). { x.serialize(); } inside requires causes shift/reduce clashes with blocks → (ERROR) nodes drop concept → GTD FAILS.

✅ Clang-Pseudo (cxx.bnf): Generated from official ISO C++ BNF with exact productions (concept-definition, type-constraint). Indexes concept as 1st-class symbol → GTD SUCCEEDS on both class and concept!

The Bracket Dilemma: Preprocessor vs. Unclosed Braces

❌ Tree-sitter Bracket Fragility

// 1. Competing Branch Brackets:
#if USE_V2 class Svc { #else class Old { #endif
// -> Cascaded (ERROR) nodes across the file!

// 2. Unclosed '{' in Function:
void helper() { int x = 10;
// <- MISSING '}'
struct TargetService { void execute(); };
// -> Tree-sitter CST: TargetService bleeds INSIDE helper()!
//    Synthesizes MISSING '}' at EOF (Scope Inversion)

Tree-sitter fails on preprocessor branches and inverts scopes on missing braces.

✅ Clang-Pseudo Architectural Reality

1. Preprocessor Branches (100% Natively Solved):
DirectiveTree::chooseConditionalBranches + stripDirectives
Prunes untaken branch BEFORE bracket pairing & GLR!
Parser sees a single, perfectly balanced token stream.

2. Unclosed '{': The Unfinished Google Bracket Pass:

Bracket.cpp: FIXME left in Phase 2 & 3
Requires completing Google's pre-pass, not ad-hoc hacks!
