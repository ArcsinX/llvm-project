  • Header-Independent: Never parses or includes transitive header code.

Semantic Navigation & Disambiguation

Distinguishing types vs. values and traversing included headers accurately.

1. Syntactic Context (isTypeContext)

  • ClangdServer::adjustParseInputs
    Followed by :: → Type context. Jumps to class ClangdServer in header, not constructor in .cpp!
  • ClangdServer::ClangdServer(...)
    1st is class in .h; 2nd before ( is constructor.
  • Foo Foo; Foo.x = 1;
    1st is struct Foo; 2nd & 3rd are local variable Foo.

2. Transitive Header BFS Search

  • Bounded Breadth-First Search (BFS) over #include directives.
  • Prioritizes quoted project headers first.
  • Avoids recursive explosion into standard library internals (<__algorithm/*>).
  • #include <vector>: Direct jump to system standard library headers.

Clang-Pseudo vs. Tree-sitter

Comparing Two Modern Header-Free Parsing Paradigms

Dimension Tree-sitter (tree-sitter-cpp) Clang-Pseudo (clang-pseudo) Advantage / Trade-off
Grammar Origin Handcrafted JS DSL (grammar.js) Official ISO C++ Standard BNF (C++20 N4860) Clang-Pseudo: Rigorous ISO compliance
Ambiguity Resolution Eager resolution via static precedence & conflicts Parse Forest DAG with global heuristic disambiguation Clang-Pseudo: Handles subtle C++ ambiguities
Preprocessor Support Parses #ifdef as syntax nodes (fragile on split tokens) DirectiveTree + Clang Lexer: Active branch selection Clang-Pseudo: Industrial macro resilience
Incremental Speed Sub-millisecond reparse on single keystroke edits Whole-file re-parse (~40–50 ms on 3,000 lines) Tree-sitter: Unmatched typing latency
Cross-File Navigation None (strictly single-file buffer syntax) Transitive Header BFS: Resolves headers & libc++ Clang-Pseudo: Powers LSP Go-to-Definition
Query Mechanism Standardized S-expression queries ((function) @fn) Native C++ AST walkers (walkSymbols, buildScopes) Tree-sitter: Universal query DSL
Primary Sweet Spot In-editor highlighting, folding & text objects Resilient LSP intelligence & compiler fallback Complementary Technologies

Use Cases & Roadmap

Target Use Cases

  • Massive Monorepos & Cloud IDEs: Eliminates multi-second CPU freezes upon opening files or switching branches.
  • Unconfigured / Newly Cloned Repos: Immediate out-of-the-box browsing before build systems configure.
  • Resource-Constrained Environments: Containerized or embedded environments where 300MB/file is prohibitive.

Future Roadmap

  • Incremental GLR Parsing: Keystroke-level instant re-parse.
  • Text-Based Semantic Completion: Approximate completions without compiler invocation.
  • Syntax-Directed Fast Refactoring: Lightweight local renames.
